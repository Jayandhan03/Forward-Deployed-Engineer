## 1. Routing & path operations
Code: [routing-and-path-operations.py](../../01-backend/02-fastapi/01-routing-and-path-operations/practice/routing-and-path-operations.py)

- **What:** `@app.get/post/put/delete("/path")` maps an HTTP method + path to a function. `APIRouter(prefix, tags)` groups routes by feature.
- **Why:** this is the entry point of every endpoint, and FastAPI reads your function signature to build parsing, validation and docs.
- **How:** the source of each argument comes from how you declare it: name in the path → path param; plain type → query param; `Header()` / `Cookie()` → header / cookie; Pydantic model → JSON body. `status_code=201` sets the success code. Include routers with `app.include_router(...)`.
- **When:** every endpoint. One router per feature (`users`, `items`), included in `main.py`.
- **sync vs async:** `def` handlers run in a thread pool; `async def` handlers run on the event loop. Use `async def` only if everything inside is awaited (async DB driver, `httpx.AsyncClient`). A blocking call inside `async def` freezes the whole server.
- **Gotcha:** declare fixed paths (`/items/me`) before dynamic ones (`/items/{id}`).

## 2. Request models
Code: [request-models.py](../../01-backend/02-fastapi/02-request-models/practice/request-models.py)

- **What:** a Pydantic `BaseModel` as a handler parameter is the JSON body. Models can nest and carry defaults.
- **Why:** typed input, automatic parsing and coercion (`"31"` → `31`), a precise 422 error (`['body','address','zip'] Field required`) and docs, with no hand-written parsing.
- **How:** `def create(user: UserIn)`. With two or more body params the JSON is keyed by param name. Use `Annotated[int, Query(ge=1, le=5)]` for constrained query params and `Annotated[str, Form()]` for HTML-form bodies (needs `python-multipart`).
- **When:** any POST/PUT/PATCH. Models for bodies, plain params for path/query.

## 3. Validation with Pydantic v2
Code: [validation-with-pydantic.py](../../01-backend/02-fastapi/03-validation-with-pydantic/practice/validation-with-pydantic.py)

- **What:** the rules engine behind request and response models.
- **Why:** invalid data should be rejected at the edge, once, with a clear message, and never reach your business code.
- **How, in order of simplicity:**
  1. `Field(ge=, min_length=, pattern=)` for constraints.
  2. `Annotated[str, Field(...)]` for a reusable type.
  3. `@field_validator("x")` for a custom rule on one field.
  4. `@model_validator(mode="after")` for cross-field rules (password == confirm).
  5. `ConfigDict(extra="forbid")` to reject unknown fields.
- **When:** put rules in the model, not in handlers. `extra="forbid"` stops mass-assignment (`is_superuser: true`). `strict=True` turns off coercion when you need exact types.

## 4. Response models
Code: [response-models.py](../../01-backend/02-fastapi/04-response-models/practice/response-models.py)

- **What:** `response_model=UserOut` declares what leaves the API. FastAPI filters the returned object down to those fields.
- **Why:** it stops accidental leaks (`password_hash`), fixes the response shape in the OpenAPI docs (and generated frontend clients), and serializes types like `datetime`.
- **How:** keep separate models: `UserIn` (input), `UserOut` (public), and the DB model (internal). `from_attributes=True` lets `UserOut` be built from ORM objects. `response_model_exclude_none=True` hides nulls. `list[UserOut]` for collections.
- **When:** every endpoint that returns data. Never reuse the input model as the output.

## 5. Dependency injection
Code: [dependency-injection.py](../../01-backend/02-fastapi/05-dependency-injection/practice/dependency-injection.py)

- **What:** `Depends(fn)` in a parameter means "run this first and pass me the result". Dependencies can depend on other dependencies.
- **Why:** it keeps handlers tiny, shares logic (auth, DB session, pagination, permissions), and makes tests easy: swap a dependency instead of patching globals.
- **How:**
  - A `yield` dependency gives setup and cleanup (DB session opens, then closes after the response, even on error).
  - A factory returning a function gives a parametrised dependency (`require_role("admin")`).
  - `DB = Annotated[Session, Depends(get_db)]` is a short alias for signatures.
  - In tests: `app.dependency_overrides[get_current_user] = lambda: fake_user`.
- **When:** any time two handlers need the same thing: a DB session, the current user, settings, pagination params, a permission check. This is the most important FastAPI concept.

## How these fit (the request path)
`request → routing (match method+path) → dependencies run (auth, db) → body validated (request model) → handler → response_model filters output → JSON`
