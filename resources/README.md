# Resources

Read alongside the work, not before it. A book you read cover‑to‑cover before building teaches less
than a chapter read the day you hit the problem it describes.

## Books

| Book | For domains | How to use it |
|---|---|---|
| **Designing Data‑Intensive Applications** — Kleppmann | 01, 05, 06 | The backbone. Read ch. 1–3, 5, 7 early; the rest as system design deepens. |
| **Clean Architecture** — Martin | 00, 01 | Boundaries, dependency rule, keeping frameworks at arm's length. |
| **The Pragmatic Programmer** — Hunt & Thomas | 00, 02, 08 | The habits. Read once, revisit a chapter when it bites. |
| **Database Internals** — Petrov | 01, 06 | What Postgres/Redis do underneath. Skim part I, read part II. |
| **Web Scalability for Startup Engineers** — Ejsmont | 05, 06 | Practical scaling for a small team; less theory than DDIA. |
| **Architecture Patterns with Python** — Percival & Gregory | 01 | Repository / unit‑of‑work / service layer with real Python. |
| **Fluent Python** — Ramalho | 00 | The Python data model done right. Ch. 1, 7–9, 17–21. |
| **System Design Interview** vol. 1–2 — Alex Xu | 06 | The case‑study format and vocabulary. |
| **Refactoring UI** — Wathan & Schoger | 04, 08 | The UI/UX shortcut for engineers. |
| **The Mom Test** — Fitzpatrick | 08 | How to talk to users without lying to yourself. |
